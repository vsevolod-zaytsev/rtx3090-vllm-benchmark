# Бенчмарк пяти LLM на одной NVIDIA RTX 3090 (vLLM, Docker)

Набор для воспроизведения **количественного** контура эксперимента из работы Зайцева В.В.: локальный инференс пяти моделей через **vLLM**, один GPU, русскоязычный корпус из **100** вопросов. Полная постановка, качественная методика (**три LLM-арбитра**, шкала 0–10), интерпретация и таблицы — в файле **`analysis.txt`** (текст набран в разметке Markdown).

## Состав каталога

| Файл / путь | Назначение |
| :--- | :--- |
| `analysis.txt` | Полный текст исследования (Markdown внутри `.txt`). |
| `questions.txt` | Корпус вопросов в читаемом виде (**экспорт списка `QUESTIONS`** из Jupyter-блокнота). |
| `llm_benchmark.ipynb` | Jupyter-блокнот: загрузка вопросов, опрос локального OpenAI-совместимого API, телеметрия GPU через SSH. |
| `benchmark_results.csv` | Пример **результата прогона** (выгрузка в той же табличной форме, что создаёт Jupyter-блокнот; UTF‑8 BOM). При собственном запуске файл сохраняется в рабочем каталоге Jupyter-блокнота. |

| `rtx3090_five_models_vllm/vllm-guard/guard-start.sh` | Стартовый скрипт: не допускает одновременного запуска двух моделей на одном хосте. |

## Запуск инференса (Docker Compose)

Требования: **Linux**, драйвер NVIDIA, Docker с **NVIDIA Container Toolkit**, собранный образ `vllm-gemma4:latest` (или замените `image:` в compose на свой).

1. Положите веса моделей в каталог на машине с GPU и смонтируйте его в контейнеры. По умолчанию compose ожидает **`./models`** относительно файла `docker-compose.yaml`. Другой путь задаётся переменной окружения перед `docker compose`, например:

   ```bash
   export BENCHMARK_MODELS_DIR=/data/benchmark_models
   ```

2. Поднимайте **строго один** сервис модели за раз (guard блокирует конкурирующий старт).

3. Внешние порты по умолчанию: **18101** … **18105** (соответствуют сервисам в Jupyter-блокноте; при необходимости синхронно поправьте `MODELS` в Jupyter-блокноте).

Подробнее о флагах `--max-model-len`, `--enforce-eager` и т.д. — в **разделах 2–3** файла `analysis.txt`.

## Jupyter-блокнот `llm_benchmark.ipynb`

1. Переменные окружения (плейсхолдеры в коде можно не трогать, если задать окружение):

   - **`BENCHMARK_SSH_HOST`**, **`BENCHMARK_SSH_USER`**, **`BENCHMARK_SSH_PASSWORD`** (или иной способ входа по вашей политике безопасности),
   - **`BENCHMARK_SSH_PORT`** (по умолчанию 22),
   - **`BENCHMARK_COMPOSE_DIR`** — каталог на GPU-узле, где лежит этот compose-проект (для `docker compose`).
   - **`OPENAI_API_KEY`** — для локального vLLM обычно подставляется служебная строка; для облачных эндпоинтов нужен реальный ключ.

2. Параметры генерации по умолчанию в коде: **`MAX_TOKENS = 1024`**, **`TEMPERATURE = 0.1`**. Выходной файл **`benchmark_results.csv`** (UTF-8 с BOM для Excel на Windows).

## Полнота и актуальность (что именно воспроизводит этот репозиторий)

**Согласовано с текстом работы:**

- Набор моделей (**gemma-4-26b**, **qwen3-coder**, **yandexgpt-5-lite-8b**, **phi-4**, **deepseek-r1-32b**), платформа одного **RTX 3090**, схема изоляции через **guard** и скрипт **`guard-start.sh`**.
- Корпус: **100** вопросов, **10** категорий (см. §3.1 в `analysis.txt` и `questions.txt`).
- Конфигурация compose, параметры экспериментального протокола (§3.2), Jupyter-блокнот **`llm_benchmark.ipynb`** — описаны и согласованы в тексте работы (**табл. 2** и §§2–3).

**Что этот архив сознательно не содержит:**

- Веса моделей (объём; размещаются локально под `BENCHMARK_MODELS_DIR` / `./models`).
- Сырые таблицы оценок **трёх арбитров** и агрегированные качественные ранги — они описаны методически в статье, но не включены как отдельные CSV в этот каталог.
