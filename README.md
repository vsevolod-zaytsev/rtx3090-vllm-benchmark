# Сравнительный анализ результативности пяти LLM на графическом процессоре NVIDIA RTX 3090 (vLLM, Docker)

Материалы репозитория предназначены для **воспроизведения этапа сбора данных** эксперимента из работы Зайцева В.В.: локальный инференс пяти моделей средствами **vLLM**, один GPU, русскоязычный корпус из **100** вопросов. Полная постановка эксперимента, методика **качественной оценки ответов тремя LLM-арбитрами** (шкала 0–10), интерпретация и таблицы приведены в файле **[analysis.md](analysis.md)** (разметка Markdown).

## Запуск инференса (Docker Compose)

**Требования:** ОС Linux, драйвер NVIDIA, Docker с **NVIDIA Container Toolkit**, собранный образ `vllm-gemma4:latest` (либо в `docker-compose.yaml` задаётся иной `image:`).

1. Веса моделей размещаются в каталоге на машине с GPU и монтируются в контейнеры. По умолчанию compose ожидает каталог **`./models`** относительно `docker-compose.yaml`. Иной путь задаётся переменной окружения перед вызовом `docker compose`, например:

   ```bash
   export BENCHMARK_MODELS_DIR=/data/benchmark_models
   ```

2. Одновременно допускается не более **одного** сервиса модели (механизм guard блокирует конкурирующий старт).

3. Внешние порты по умолчанию: **18101** … **18105** (согласованы с Jupyter-блокнотом; при изменении порта синхронно обновляется словарь `MODELS` в Jupyter-блокноте).

Параметры командной строки vLLM (`--max-model-len`, `--enforce-eager` и др.) изложены в **разделах 2–3** [analysis.md](analysis.md).

## Jupyter-блокнот `llm_benchmark.ipynb`

1. Переменные окружения (плейсхолдеры в коде можно не менять, если задано окружение):

   - **`BENCHMARK_SSH_HOST`**, **`BENCHMARK_SSH_USER`**, **`BENCHMARK_SSH_PASSWORD`** (или иной способ аутентификации в соответствии с политикой безопасности),
   - **`BENCHMARK_SSH_PORT`** (по умолчанию 22),
   - **`BENCHMARK_COMPOSE_DIR`** — каталог на GPU-узле с данным compose-проектом (для `docker compose`),
   - **`OPENAI_API_KEY`** — для локального vLLM обычно задаётся служебная строка; для облачных эндпоинтов требуется действительный ключ.

2. Параметры генерации по умолчанию в коде: **`MAX_TOKENS = 1024`**, **`TEMPERATURE = 0.1`**. Выходной файл **`benchmark_results.csv`** (UTF-8 с BOM для совместимости с Microsoft Excel на Windows).

## Полнота материалов репозитория

**В состав включено** (согласовано с текстом работы и с [analysis.md](analysis.md)):

- Набор моделей (**Gemma 4 26B**, **Qwen2.5-Coder-32B**, **YandexGPT 3 Lite 8B**, **Phi-4**, **DeepSeek-R1-Distill-Qwen-32B**), платформа одной **RTX 3090**, изоляция через **guard** и скрипт **`guard-start.sh`** (официальные наименования и соответствие развёртыванию — в [analysis.md](analysis.md)).
- Корпус: **100** вопросов, **10** категорий (подробнее — §3.1 в [analysis.md](analysis.md) и файл `questions.txt`).
- Конфигурация compose, параметры протокола сбора данных (§3.2), Jupyter-блокнот **`llm_benchmark.ipynb`** — описаны в работе (**табл. 2**, §§2–3 в [analysis.md](analysis.md)).

**В состав не включено** ввиду объёма дистрибутива или формата публикации:

- файлы весов моделей (размещаются локально под `BENCHMARK_MODELS_DIR` или `./models`);
- сырые таблицы оценок **трёх LLM-арбитров** и отдельные CSV с агрегированными качественными рангами — методика их применения описана в [analysis.md](analysis.md), сами таблицы в каталог не выкладываются.
